# DREAM PROTOCOL — QA 및 폴리싱 감사 보고서

범위: 전체 캠페인(침실 → CITY → BACKROOMS → THE DEEP → COMPRESSION → ABOVE), 데스크톱과
웹/모바일 빌드. 레벨, 메커니즘, 모델, 스토리는 재설계하지 않았습니다. 아래의 모든 수정은 개별적으로
테스트했으며, 모든 수정 이후에도 전체 플레이스루 테스트를 통과합니다.

## 테스트 방법

| 도구 | 내용 |
|---|---|
| `tests/flow_test.tscn` (기존) | 타이틀부터 하늘의 문까지 전체 스토리를 진행하고, 모든 죽음과 깨어나는 장면까지 확인. **통과.** |
| `tests/qa_test.tscn` (신규) | 위험한 경로를 순간이동 대신 실제 이동 입력으로 **걸어서** 확인: 계단, 경사로, 아치, 덕트, 두 추격전, 불가능한 문들. 목표 텍스트와 세이브 저장/불러오기도 확인. **통과.** |
| `tests/perf_probe.tscn` (신규) | 구역별 드로우 콜, 오브젝트, 삼각형, 조명, 그림자 조명, 노드 수. |
| `tests/perf_top.tscn` (신규) | 구역에서 가장 무거운 메시 목록. |
| 정적 검사 | 재생되는 모든 사운드 이름이 존재함(모두 존재). 모든 구역의 저장·복원 가능. 구역 간 DREAD 설정 비교. |
| 모바일 브라우저(에뮬레이션) | 한 손가락·두 손가락 터치 조작. |

아래 문제 대부분은 플로우 테스트로는 발견할 수 없었습니다. 플로우 테스트는 스토리 지점 사이를
순간이동하기 때문에 경로를 실제로 걷지 않습니다. 새 QA 테스트는 걷습니다.

## 2. 게임플레이 개선

수정 완료:
- **목표에 원시 자리표시자가 표시됨**: 첫 카운트 전까지 "Change something in the dream ({changes}/2)"처럼, 세이브를 불러온 후에는 "5.0"처럼 보였음. 이제 카운터는 0부터 시작하는 정수로 항상 표시됨.
- **ABOVE: 돌풍이 새로 만든 좁은 구간까지 영향을 줌**(떠 있는 계단, 크레인 대들보, 경로 타일). 돌풍 한 번에 옆으로 약 2m 밀려 첫 옥상으로 돌아감. 이제 돌풍은 원래 설계되고 안내된("웅크리세요") 첫 옥상들과 대들보에만 적용됨.
- **일기장과 노트의 마일스톤**이 `elif`로 연결되어 있어, 둘 다 해제하는 플래그가 생기면 노트 문장이 조용히 사라졌을 것. 이제 둘 다 항상 처리됨.
- **존재하지 않는 구역의 세이브**(향후 이름 변경 시)는 빈 장면으로 로드되었음. 이제 이어하기가 새 게임을 시작함.
- **터치에서도 모든 조작이 가능해짐:**
  - 사물을 탭하면 사용(E와 동일);
  - ◀ ▶로 상상할 대상 변경;
  - 이미 본 죽음은 SKIP;
  - JUMP와 CROUCH는 누르고 있는 동안 유지되어 수영 상승·하강 가능.
  - 힌트와 목표에 키 대신 터치 버튼 이름이 표시됨.

권장(미적용: 동작을 바꾸는 사항이라 승인이 필요함):
1. **긴 구역 내부에 체크포인트 추가.** 현재는 구역에 들어갈 때만 저장됨. ABOVE의 스카이웨이(7단계 중 6단계)에서 죽으면 첫 옥상으로 돌아가며, 심연과 공동주택도 정도는 덜하지만 같은 문제가 있음. 제안: 단계마다 체크포인트(리프트·계단·크레인 이후, 격벽·봉화 이후, 7층 이후). 세이브에 단계를 기록하고 각 구역이 해당 단계의 상태를 재구성해야 하므로 중간 정도의 작업량.
2. **오를 때의 DREAD.** 아래를 보면 공포가 빠르게 차오르는 것은 의도된 설계지만, 연출된 마스트 오르기와 떠 있는 계단에서는 플레이어가 자연스럽게 아래를 봄. 오르는 동안 공포 증가량을 절반으로 줄여 관찰자 죽음이 등반 중에 발생하지 않게 할 것을 고려.
3. **터치에서는 튜토리얼 영상을 건너뛸 수 없음**(Esc 전용). 재생 중 SKIP 버튼 추가.
4. **범용 영역 이탈 안전장치**: 낙사 처리가 없는 구역(침실, 도시, 공동주택)에서 조용한 리스폰. 지형이 다시 바뀌어 구멍이 생길 경우를 대비.
5. **리바이어던 추격은 빠듯함.** 전력 질주하면 약 7m 앞서 문에 도착하고, 걸으면 잡힘. 의도된 긴장감이지만, 달리기가 토글인 휴대폰에서 플레이테스트할 가치가 있음.

## 3. 시각 및 오디오 폴리싱

- **글러브(신규):** 방호복(백룸), 다이빙(THE DEEP), 작업용(COMPRESSION), 가죽(ABOVE), 그 외에는 맨손. 구역에 들어가면 교체됨.
  - 손가락 관절의 주름이 약간 규칙적임.
  - 가까이서 보면 가죽 결이 강함.
  - 맨손의 손톱이 작음.
  - `tools/creatures/hands.py`에서 주름을 다양화하는 2차 작업 가능.
- **웹 렌더러:** 브라우저 빌드는 Godot의 Compatibility 렌더러를 사용. 피부 서브서피스 스캐터링과 볼류메트릭 포그가 없고 오브젝트당 조명 수가 제한되어, 백룸의 43개 조명 중 일부가 브라우저에서 빠질 수 있음. 실제 브라우저에서 모든 구역을 시각적으로 확인할 가치가 있음.
- **오디오:** 65개의 합성 사운드가 모두 존재하며 모든 참조가 연결됨. 단발로 재생되던 루프 사운드(grind, motor, static, breath, wind)는 이제 무한 반복 대신 한 번만 재생됨.
  - 권장: 스팅어 전반의 음량 정리.
  - 권장: 중요한 소리(노크, 숨소리, 리바이어던)에 대한 선택적 자막. 접근성과 소리를 끈 모바일 플레이어를 위해.

## 4. 성능

각 구역 시작 지점에서 30프레임 평균으로 측정. 삼각형 수에는 그림자 패스가 포함됨.

| 구역 | 드로우 | 삼각형(이전) | 삼각형(이후) | 조명(그림자) |
|---|---|---|---|---|
| 침실 | 44 | 28k | 28k | 4 (2) |
| 도시 | 592 | 4.6M | 4.6M | 0 |
| 백룸 | 139 | 134k | 134k | 43 (4) |
| THE DEEP(수영장) | 203 | **6.8M** | **0.39M** | 34 (5) |
| 해저 | 52 | 155k | 155k | 27 (1) |
| 심연 | 89 | 71k | 71k | 28 (0) |
| Compression | 169 | 131k | 131k | 17 (3) |
| 공동주택 | 57 | 47k | 47k | 30 (2) |
| ABOVE | 158 | 1.0M | 1.0M | 17 (2) |

추가 적용: 작게 흩뿌려진 오브젝트(잔디)는 카메라가 컬링할 수 있는 셀로 나누고 70m 밖에서는 사라지게 함.

권장:
1. **도시: 비용의 원인은 건물 외벽.** 장면에 290만 개의 삼각형이 있으며, 대부분 스카이라인의 외벽 모듈 5,360개와 그림자를 드리우는 가까운 건물의 모듈 약 6,500개임. 그림자 패스까지 세면 460만 개가 렌더링됨.
   - 외벽을 컬링 셀로 나누니 삼각형은 절반이 되었지만 드로우 콜이 거의 두 배가 되어, 실제 GPU에서 측정할 수 있을 때까지 되돌림.
   - 더 나은 방법:
     - 스카이라인 건물마다 하나의 로우폴리 메시로 합치기(임포스터);
     - 스카이라인 모듈의 그림자 끄기;
     - 그림자를 가까운 블록으로 제한하기.
2. **ABOVE:** 장면의 17.4만 개가 렌더링 시 100만 개가 됨. 그림자 캐스케이드가 스카이라인 타워를 몇 배로 늘림. 같은 해결책 적용 가능.
3. **웹 다운로드는 47MB**(그중 31MB가 텍스처). 권장:
   - 웹 빌드에서 먼 표면의 텍스처를 절반 크기로;
   - 웹용 압축 텍스처 포맷 사용;
   - 글러브 맵을 512px로 축소(가까이서 보이지만 1024px × 5종이 약 13MB).
4. 측정 도구의 CPU 시간은 소프트웨어 렌더러 기준이라 의미가 없음. 릴리스 전에 중급 휴대폰과 저사양 노트북에서 프로파일링할 것.

## 5. 릴리스 준비 권장 사항

1. **빌드할 때마다 세 가지 테스트 실행:** `flow_test`(스토리), `qa_test`(걸을 수 있는 경로, 추격전, 세이브), `perf_probe`(예산).
   - 새 경로를 만들 때마다 `qa_test`에 검사를 추가할 것. 이번 감사의 치명적 버그는 모두 스토리 테스트가 순간이동으로 지나치던 곳이었음.
2. **실제 기기에서 플레이테스트:** 휴대폰(터치, 성능, 오디오 잠금 해제), 태블릿, 웹 빌드를 실행한 저사양 노트북. 에뮬레이션 휴대폰은 조작만 확인하며 프레임 속도는 확인하지 못함.
3. **구역 중간 체크포인트 여부 결정**(게임플레이 1번). 남은 가장 큰 편의성 공백.
4. **세이브 형식 버전 관리.** 현재 버전 1이며 마이그레이션이 없음. 릴리스 전에 마이그레이션 단계를 추가하거나, 최소한 새로 추가된 "알 수 없는 구역 → 새 게임" 안전장치를 유지할 것.
5. **익스포트 설정 커밋 또는 문서화.** `export_presets.cfg`가 git에서 제외되어 있어 웹 익스포트가 로컬 파일에 의존함. `tools/web/build.sh`에 문서화(일부 완료)하거나 템플릿을 커밋할 것.
6. **서드파티 에셋(Quaternius 모델)의 크레딧과 라이선스**를 게임과 README에 기재할 것.
